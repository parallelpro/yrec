# io/ — controls in, output and models out

This directory holds the run's input and output:
- the controls reader, which turns a deck into `star%control` and `star%physics`, the records of its `&control` and `&physics` groups;
- the run's files: their unit numbers and paths, the output directory, the run log, and the run plan from the kind cards;
- the output: the history and profile files in MESA's layouts, the pulsation files, and the progress lines in the run log;
- the stellar model files: the `.mod` model (the restart file), and the readers of the older YREC7 and MODEL2 starting models.

The physics never reads a deck or writes a file itself. It reads its controls from `star%control` and `star%physics` (a domain, from its settings record, built in `setup/`), and the values the run changes from their run copies, star members, and the output reads what the step computed: `compute_observables` and the stitched model (`core/diagnostics/`) compute every quantity first, and the writers take the star `intent(in)`.

Every io procedure that touches the star takes it as an argument, `s` (`type(star_info)`), as core's procedures do, and nothing in io names a module-level star (`tools/check_boundaries.py`, `STAR_ACCESS_BUDGET`). The output's own state is one record, `output_state` (`yrec_output`), which `run_yrec` owns and passes in. The run's messages, and the gate for the solver forensics that star-free code asks too (`solver_diagnostics()`), are `state/run_messages.f90`'s, a module every layer may use: no physics domain imports a module of io (`check_physics_no_io`).

## 2. A run

`run_yrec` (`core/run/run_driver.f90`):
1. `read_controls` turns the deck into `star%control` and `star%physics`; it opens no file of the run, but for the run log after a controls error (sub-step 4). A deck is either a single-file inlist, one file holding a `&control` and a `&physics` group under the inlist names, or a legacy CONTROL/PHYSICS namelist pair (`.nml1`/`.nml2`) under the legacy names; the legacy groups are the inlist's groups except seven controls that the CONTROL namelist holds and the inlist's `&physics` (`log_output_file`, `terminal_interval`, `report_solver_diagnostics`, `nu_max_sun`, `delta_nu_sun`, `Teff_sun`, `profile_data_prefix`; `tools/upgrade_inlist.py` places them). An inlist with the group names of 2026-08 to 2026-10, `&star_job` and `&controls`, stops the run with the command that renames them. `read_controls` runs, on the buffer:
   1. `seed_controls_buffer`: `star%control` and `star%physics` to their declared defaults (a test checks that a deck setting nothing reads exactly these), copied into the buffer, and the buffer-only members to theirs.
   2. `read_input`: the fixed units, the deck's files (the command line, or an embedding host's override), and the deck read over the buffer, straight into the code names. An inlist's groups (`read_inlist`, the generated `inlist_decl.inc` and `inlist_read.inc`) bind the buffer members themselves where the inlist name is the code name (342 of 380), and otherwise a local named for the inlist name, which starts at the code name's default and is copied into it after the read. An alias, an older inlist name, is a local too; the groups are read twice, the aliased names seeded with another value the first time, so that the read knows, element by element, which names the deck sets (below, "A control's names"). A legacy pair is read by `read_legacy_deck`: each legacy variable takes its code name's default, the two namelists are read, and each value is copied to its code name.
   3. `map_user_inputs` (`io/user_inputs.f90`: the rate scales and the readable tolerances) and `expand_paths` (every path control's placeholder).
   4. `check_controls` (an error stops the read with ierr = 1; the read then opens the run log alone, `open_run_log_after_error`, at the deck's path, so that it holds the read's lines and the error), `warn_inert_controls`, `derive_controls` (with the run log's header), `interpret_kind_cards` (the run plan).
   5. `store_controls_to_star`: `star%control` and `star%physics` from the buffer; then `arm_run_copies` sets each run copy (below) from its control, as `begin_monte_carlo_run` does again at the start of every Monte-Carlo run, so that each Monte-Carlo run starts from the deck's values. The read writes nothing else on the star.

   Every read starts from the same state, so an in-process rerun (pyyrec, `test_reentry`) reads exactly as a fresh run does.
2. After the read, `run_yrec` calls `open_run_files(s, ierr)`, which creates the output directory (the run log's) and opens the run log first, so that it receives the read's lines (its header, the run plan, the warnings, in order) and any error after them; then it copies the deck to `inlist_used` there, and opens the starting model, the final-model file, and the Monte Carlo and isochrone files when they are on, each from its path control in the star. A starting model that cannot be opened (the `sample_cases/LowM_HB` decks name one that does not exist) stops the run here, with the run log holding the header, the run plan and the error. A controls error stops the run at the read, which has opened the run log alone for it (step 1.4); a deck that cannot be read stops the run before its paths are expanded, when the run log's path is not the deck's yet, and its messages are on the terminal only. Then `output_open` (step 3), `prepare_run` (which sets the run plan's envelope Z and the EOS mixture, copies the solar units to the star and installs the per-run records of kap, eos and atm with their tables, `install_run_settings`) and `warn_inconsistent_controls`. Each Monte Carlo run starts with `begin_monte_carlo_run` (the run copies re-armed, then the run's samples applied) and installs the network's record (`install_monte_carlo_settings`), and each run card's `begin_kind_card` the card's (`install_card_settings`: convection, rotation, element diffusion); `setup/`'s builders make them from `star%control`, `star%physics` and the run copies, and `setup/settings_install.f90` installs them.
3. `output_open`: the history file's path and columns, the profile columns, and the pulse format. An unknown pulse format, or GSM on a build without HDF5, stops the run here (exit 1), as does a bad columns file. A history file a previous call left open is closed.
4. At each card, `read_starting_model` (`core/model/starting_model.f90`) reads the starting model when the card asks for it: `read_model_format_tag`, then `read_mod_model`, `read_yrec7` or `read_model2`; and `output_run_header` writes the card's line on the terminal (and the isochrone header).
5. Each converged model, `evolve_step` builds the stitched model (`build_stitched_model`: every profile column at every point of the interior, envelope and atmosphere, and the pulse points), computes the observables, and calls `output_write_model`: the progress line every `terminal_interval` models; the isochrone record; every `profile_interval` models, `profile<N>.data` and its pulsation file `profile<N>.data.<format>`; the history row (its `profile_number` is that N, or 0); the `.mod` model; and every `pulse_gyre_interval` models the interior GYRE file `profile<model>.data.GYRE` (`write_interior_gyre`), whatever `write_pulse_flag` says.
6. At each card's end, the progress line of its last model (`output_final_model_line`).
7. At the end, the summary (`log_run_summary`), the Monte Carlo summaries (`core/run/monte_carlo.f90`, which appends each run's model to the Monte Carlo model file), and `output_close` (the history file closed; each row was checked on disk as it was written).

Every write of steps 2-7 is checked: a failed one stops the run with exit 1 and its message (§3).

A job's files, in its output directory (the run log's, from `log_output_file`):
- the run log (`.log`; a legacy `.short` name becomes `.log`): the header, the run plan, warnings, the progress lines, the summary, and the solver forensics when `report_solver_diagnostics` is on;
- `inlist_used`, the deck as read;
- the history file (`star_history_name`, default `history.data`): one row per converged model;
- `profile<N>.data` and its pulsation file, when `write_profile_flag` and `write_pulse_flag` are on, and the interior GYRE files when `pulse_gyre_interval` is positive;
- the `.mod` model (`last_model_file`), rewritten every model: the restart file, and the solver's recovery source when a step fails.

## 3. Conventions

- Output columns keep their MESA names and layouts (`test_mesa_output`, `test_mesa_baselines`); a column's index is named after it (`ih_star_age`, `ip_logT`).
- Units: CGS unless the name has a unit suffix (`_msun`, `_gyr`, `_yr`); log is log₁₀. The history's `star_age` is in years and its luminosities in Lsun, as MESA's.
- The profile's `eps_ppI` .. `eps_he3` are fractions of `eps_nuc`, one per chain with a slot (`eps_he3` is the triple-α share); the α captures have none, so where they burn the five add up to 1 minus their share (in core helium burning that share reaches nearly all of `eps_nuc`). `eps_nuc`, `eps_neu` and `eps_grav` are erg/g/s.
- The pulsation files' ε: GYRE and GSM write ε = `eps_nuc`, the chains' sum without the thermal neutrino loss, with that ε's derivatives `eps_eps_T`, `eps_eps_rho` (absolute, dε/dln T), as MESA writes `eps_nuc` with `d_epsnuc_dlnT` and `d_epsnuc_dlnd`; FGONG's `var(9)` is the same ε. `kap_kap_T` and `kap_kap_rho` are κ dln κ/dln T and κ dln κ/dln ρ.
- Errors return `ierr = 1`, which stops the run with exit status 1. io reports them through `run_messages` (`state/run_messages.f90`): `check_io` after an open, read or write (`ERROR: cannot <action> <path>: <reason>`), and `report_error` otherwise (`ERROR: <text>`), on the terminal and in the run log once it is open. A starting model that cannot be read, whose zone count does not fit the arrays, or that ends early, is such an error, as is a profile column without a value in a region, and a write that fails.
- Every write of a file is checked. A writer writes with `iostat` and `iomsg`, skips the writes after the first that fails, and reports it (`output_files`; the `.mod` and the isochrone file, which stay open for the run, through `check_io` at each write, and the history rows through `flush_output_file`). A full disk needs one more check: gfortran's runtime drops the bytes a full disk refuses and reports nothing on the write, the flush or the close (measured on a 2 MB disk image: every `iostat` 0, the file cut short). So after the flush, `flush_output_file` compares what the unit wrote (`inquire` by unit, which gfortran answers from its own count of the bytes it was given) with the size of the file the unit has open, read through its descriptor (gfortran's `fnum` and the C library's `lseek`), and a shorter file is `ERROR: cannot write <path>: the file on disk is shorter than what was written to it (is the disk full?)`. The file measured is the unit's own, not whatever the path names by then, and it is measured right after the flush: decks that share an output directory all write `history.data`, and another run's open (`status='replace'`, which gfortran makes on the existing file, truncating it in place) is not this run's write failing (M174). That covers the files io closes, the profiles, the pulsation files and the copy of the deck, at their close, and the history file at each row (its close checks only the close); the `.mod` and the isochrone file, open for the run, are not covered. GSM (HDF5) checks every library call's status.
- The other messages go through `run_messages` (`state/run_messages.f90`) too, each on the terminal and in the run log: `report_warning` (`WARNING: <text>`, a probable mistake the run goes on with: the controls' warnings of `warn_inert_controls`, `warn_inconsistent_controls` and `derive_controls`), `report_note` (a line saying what the read did), and `log_line` (a line for the run log only: its header, the run plan). A message from before the run log opens waits for it: `open_run_log` writes the waiting lines first, so the run log holds them in order. The run log is the first file `open_run_files` opens, and after a controls error it is opened alone (§2), so a run that stops holds its reason in the run log; only a deck that cannot be read at all, and a run log that cannot be opened, leave the messages on the terminal only.
- The `.mod` model holds one model, the latest (`write_mod_model(..., replace=.true.)`); the Monte Carlo model file holds one per run (`replace=.false.`). Its rows are written at full precision (es26.16e3), so a reload between cards gives the model back bit for bit.
- Paths: every path control may start with `{YREC_INPUT}`, `{YREC_START}` or `{YREC_OUTPUT}`: that environment variable's value, or `../../input`, `../../startmodels` or `output` when it is unset or empty.
- FGONG's globals 4-6 are the run's initial Z and X, the first card's starting composition (the history header's `initial_z` and `initial_x`), and the model's mixing length, as MESA writes `initial_z`, `1 - initial_y - initial_z` and `mixing_length_alpha`.
- `pulse_format` is GYRE, FGONG or GSM, in any case.

**The two records, the run copies and the buffer.** The star holds the deck's controls in two records named for the inlist's namelist groups; a control is in the record of its registry `group` (a derived member, which no deck sets, takes the group of its topic). The output's controls are in both:

|---|---|---|

| `star%physics` (`&physics`) | the physics and the numerics: the solar units, the timestep and zoning, the Newton iteration, the cutoffs, burning and the rate scales, the EOS, the opacities, convection, the atmosphere and the envelope, rotation and magnetic braking, mass change, settling, the starting model's species change, Monte Carlo; and of the output `star_history_name`, `profile_interval`, `profile_data_prefix`, `pulse_format`, `write_profile_flag`, `write_pulse_flag`, `terminal_interval`, `compute_neutrino_fluxes`, `log_output_file` | the builders in `setup/` (each domain's settings record), core's stages and drivers, the writers |

The records never change after the read: only `io/controls_sync.f90` assigns them. A control keeps the deck's value; the run changes its run copy. `report_solver_diagnostics` stays in the buffer: the read installs it as `run_messages`' gate, which the run asks. The registry's `home` column says where each control lives; `tools/check_boundaries.py` fails when the code disagrees (a control assigned outside the read, a run copy nothing outside the read assigns, a buffer member code outside the read reads, a control in the other group's record), when the `used` column (`run`, `read`, `none`) does, and when a run copy is not declared, documented and armed as its control (a writer the copy's comment names may restore it from its control, as the surface boundary does for the atmosphere). A latch that the run switches and every card re-arms is a star member armed from its control at each card (`star%settling_active` from `physics%diffuse_helium_active`), not the control itself. The Monte-Carlo samples (`star%mc_samples`) and the card cursor `current_card` are run data, not controls.

**A control's names.** A namelist matches a deck's entries by variable name, so the legacy decks fix the legacy spellings (`KTTAU`). In the code a control has its code name (`atm_choice`, in `controls_buffer` and `star%physics`); its inlist name is usually the code name. An inlist name that misdescribed its control was replaced, and the old one is still accepted as an alias (`new_zone_omega_weight` for `cz_rotation_law_exponent`, `kurucz_atm_table_file` for `kurucz_opacity_table_file`, ...). An alias counts, element by element, where the deck sets it and not the new name: a deck that sets the new name gets its value even when that is the default, an array split across the two names gets each part, and a deck that sets both names for an element gets the new one's value and a warning. `defaults/controls_registry.tsv` maps the names (`tools/controls_registry.py` describes its columns and the statuses `live`, `legacy`, `unused`, `derived`; `defaults/controls_registry.md` is the generated table, with each control's default and description from controls_buffer). The legacy CONTROL/PHYSICS namelists are frozen (the Solberg-Hoiland pair, of 2026-10-29, is the one later addition): a control added since has the legacy name `-`, and is read by the inlist only.

**Table paths.** Every table file is a path control in `star%control` (`laol_table_path`, `zams_a_table_path`, `alex95_table_paths(7)`, ...; `opal_eos_table_path`, the OPAL EOS vintage's, is derived, in `star%physics`): its registry type is `path`, so the read expands its placeholder (`expand_paths.inc` is generated from the path rows). The builders `kap_table_paths_from_star`, `eos_table_paths_from_star` and `atm_table_paths_from_star` (`setup/kap_settings_builder.f90`, `eos_settings_builder.f90`, `atm_settings_builder.f90`) copy them into each domain's paths record, which `kap_init`, `eos_init` and `atm_init` take (`install_run_settings`, `setup/settings_install.f90`).

**Where a check goes.** A value or combination the run cannot use: `check_controls`, with ierr = 1 and `report_error` naming the control (and its legacy name). A setting that is legal but inert: a warning in `warn_inconsistent_controls` (or, for a legacy-only name, `warn_inert_controls`), through `report_warning`. A domain's own consistency checks on its settings stay in the domain.

The wind law's coefficients, the convection zone's rotation-law clamp and the solid-body flag are not controls: `setup/rotation_settings_builder.f90` derives them when it builds rotation's settings (`magnetic_braking`'s `derive_wind_law`). The Bulirsch-Stoer controls (`tolerance_fraction`, `max_stage_index`, `extrap_order`) are controls in `star%physics`, and the envelope integration copies them into its kernel's settings (`envint_config`).

## 4. Tests and coverage

`test_io` (`make tests` in `src/`, then `pytest test_io.py`) checks io's own procedures against their contracts, with no deck and no tables (it writes every file it reads, in a scratch directory; `io/test/expected_test_io.out` pins the list of checks):
- `expand_value`: a leading placeholder becomes its environment variable's value (set through the C library), or its default when the variable is unset or empty; a placeholder that is not leading, a value without one and a value shorter than any placeholder stay as they are; a value that expands to a later placeholder is expanded again;
- `directory_of` (up to the last `/`, blank for a bare name) and `pulse_format_code` (any case, blanks around, anything else unknown);
- `parse_columns` on a small table: the default selection in its order; a file's names in file order, past comments and blank lines; an unknown name, a file that selects nothing, a missing file and more than `max_cols` names are errors with their messages, the unknown name's with the valid names in the run log;
- `nml_file_has_group`: a group found in any case, ended by a blank, a tab or `/`, and not as the prefix of a longer name or in a comment;
- the `.mod` model: written and read back bit for bit (every global, flag and column, at values from 1e-310 to 1e120), its columns line and a row in its order, an unknown global noted and skipped, replace and append, and the reader's errors (another columns line, a file cut inside its shells, too many zones); the format tag, and an empty file;
- synthetic YREC7 and MODEL2 files written in their layouts: every value where the layout puts it (the header, MODEL2's codes and flags, the luminosities and their conversion from erg/s, the envelope records and the reflected triangle, the structure, X and Z in units of 1e-6, the CNO and light-element blocks through the convection zones, He4 = 1 − X − Z − He3, omega and its sentinel, a rotating file without omega), and the files cut or damaged (a cut, a zone count of 0 or above `json`, a shell mass above the star's, a convection-zone edge outside the model);
- the history and profile column tables: names nonblank, short enough and unique, kinds valid, the default selections resolving in the `.list` order;
- the writes: a failed write is an error with its message, for each kind of file. A write to a unit open for reading only (which gfortran reports) stands in for a failure of the files kept open, the `.mod`, a history row and the isochrone header; a file whose directory cannot be made for an open; and a full disk, as a file-size limit (`RLIMIT_FSIZE`, with `SIGXFSZ` ignored) stands in for one, for the files io closes: the GYRE, FGONG and profile files and the copy of the deck at their close, and the history file at its row, which end up shorter on disk than what was written; two runs that write one path (M174) are not a full disk: a history file that another run truncates in place after this run's last row (the C library's `fopen` with "w", the open gfortran's `status='replace'` makes) or replaces by a new file, and a file io closes whose path another file has taken, close without error; and the size check keeps the unit's place in its file;

**CI** (`.github/workflows/ci.yml`, on every push to `main`, `yrec-next` and `modernize-readable-refactor`, on pull requests, and by hand): the six generators' `--check`, the build, `make tests`, the other-energy example and the library link checks, then pytest on every unit-test file and the deck tests that need only the solar deck's tables (test_io, test_controls, test_generated_files, test_boundaries, test_error_exit, test_mesa_output and the domains'); a second job runs the solar deck twice and byte-compares the runs. `test_mesa_baselines.py` (macOS-pinned bytes) and `test_all.py` (every deck, the full tables) stay local.

# io/ — controls in, output and models out

This directory holds the run's input and output:
- the controls reader, which turns a deck into `star%ctrl` and `star%job`;
- the run's files: their unit numbers and paths, the output directory, the run log, and the run plan from the kind cards;
- the output: the history and profile files in MESA's layouts, the pulsation files, and the progress lines in the run log;
- the stellar model files: the `.mod` model (the restart file), and the readers of the older YREC7 and MODEL2 starting models.

The physics never reads a deck or writes a file itself. It reads its controls from `star%ctrl` and `star%job` (a domain, from its settings record, built in `setup/`), and the output reads what the step computed: `compute_observables` and the stitched model (`core/diagnostics/`) compute every quantity first, and the writers take the star `intent(in)`.

Every io procedure that touches the star takes it as an argument, `s` (`type(star_info)`), as core's procedures do, and nothing in io names a module-level star (`tools/check_boundaries.py`, `STAR_ACCESS_BUDGET`). The output's own state is one record, `output_state` (`yrec_output`), which `run_yrec` owns and passes in. `solver_diagnostics()`, the gate for the solver forensics that star-free code asks too, reads the run log's own copy of the control, which the controls read installs (`set_solver_diagnostics`).

## 2. A run

`run_yrec` (`core/run/run_driver.f90`):
1. `read_controls` turns the deck into `star%ctrl` and `star%job`; it opens no file of the run. A deck is either a single-file inlist, one file holding a `&control` and a `&physics` group under the readable names, or a legacy CONTROL/PHYSICS namelist pair (`.nml1`/`.nml2`), the same groups under the legacy names in two files. An inlist with the group names of 2026-08 to 2026-10, `&star_job` and `&controls`, stops the run with the command that renames them. `read_controls` runs, on the buffer:
   1. `star%ctrl = controls_state()`, `star%job = star_job()`: the declared defaults (a test checks that a deck setting nothing reads exactly these); `seed_controls_buffer` copies them into the buffer and sets the buffer-only members to theirs.
   2. `read_input`: `set_legacy_defaults`, the fixed units, the namelist read over the defaults (an inlist's through `read_inlist`: the generated `inlist_new_decl.inc` declares its groups, which hide `legacy_controls`' groups of the same names, and `inlist_new_read.inc` seeds the inlist names from the legacy ones, reads, takes an alias the deck set, and copies back).
   3. `adopt_canonical_names`: each legacy-spelled value to its canonical name; `map_user_inputs` (`io/user_inputs.f90`); `expand_paths`.
   4. `check_controls` (an error stops the read with ierr = 1), `warn_inert_controls`, `derive_controls` (with the run log's header), `interpret_kind_cards` (the run plan).
   5. `store_controls_to_star`: `star%ctrl` and `star%job` from the buffer.

   Every read starts from the same state, so an in-process rerun (pyyrec, `test_reentry`) reads exactly as a fresh run does.
2. After the read, `run_yrec` calls `open_run_files`, which creates the output directory (the run log's), copies the deck to `inlist_used` there, and opens the starting model, the final-model file, the run log (which receives the read's messages, in order), and the Monte Carlo and isochrone files when they are on; a controls error stops the run before any of these is made. Then `output_open` (step 3), `prepare_run` (which copies the solar units to the star and installs the per-run records of kap, eos and atm with their tables, `install_run_settings`) and `warn_inconsistent_controls`. Each Monte Carlo run installs the network's record (`install_monte_carlo_settings`), and each run card's `begin_kind_card` the card's (`install_card_settings`: convection, rotation, element diffusion); `setup/`'s builders make them from `star%ctrl` and `star%job`, and `setup/settings_install.f90` installs them.
3. `output_open`: the history file's path and columns, the profile columns, and the pulse format. An unknown pulse format, or GSM on a build without HDF5, stops the run here (exit 1), as does a bad columns file. A history file a previous call left open is closed.
4. At each card, `read_starting_model` (`core/model/starting_model.f90`) reads the starting model when the card asks for it: `read_model_format_tag`, then `read_mod_model`, `read_yrec7` or `read_model2`; and `output_run_header` writes the card's line on the terminal (and the isochrone header).
5. Each converged model, `evolve_step` builds the stitched model (`build_stitched_model`: every profile column at every point of the interior, envelope and atmosphere, and the pulse points), computes the observables, and calls `output_write_model`: the progress line every `terminal_interval` models; the isochrone record; every `profile_interval` models, `profile<N>.data` and its pulsation file `profile<N>.data.<format>`; the history row (its `profile_number` is that N, or 0); the `.mod` model; and every `pulse_gyre_interval` models the interior GYRE file `profile<model>.data.GYRE` (`write_interior_gyre`), whatever `write_pulse_flag` says.
6. At each card's end, the progress line of its last model (`output_final_model_line`).
7. At the end, the summary (`log_run_summary`), the Monte Carlo summaries (`core/run/monte_carlo.f90`, which appends each run's model to the Monte Carlo model file), and `output_close`.

A job's files, in its output directory (the run log's, from `log_output_file`):
- the run log (`.log`; a legacy `.short` name becomes `.log`): the header, the run plan, warnings, the progress lines, the summary, and the solver forensics when `report_solver_diagnostics` is on;
- `inlist_used`, the deck as read;
- the history file (`star_history_name`, default `history.data`): one row per converged model;
- `profile<N>.data` and its pulsation file, when `write_profile_flag` and `write_pulse_flag` are on, and the interior GYRE files when `pulse_gyre_interval` is positive;
- the `.mod` model (`last_model_file`), rewritten every model: the restart file, and the solver's recovery source when a step fails.

## 3. Conventions

- Output columns keep their MESA names and layouts (`test_mesa_output`, `test_mesa_baselines`); a column's index is named after it (`ih_star_age`, `ip_logT`).
- Units: CGS unless the name has a unit suffix (`_msun`, `_gyr`, `_yr`); log is log₁₀. The history's `star_age` is in years and its luminosities in Lsun, as MESA's.
- The profile's `eps_ppI` .. `eps_he3` are fractions of `eps_nuc`, one per chain with a slot (`eps_he3` is the triple-α share); the α captures have none, so where they burn the five add up to 1 minus their share (in core helium burning that share reaches nearly all of `eps_nuc`). `eps_nuc`, `eps_neu` and `eps_grav` are erg/g/s.
- The pulsation files' ε: GYRE and GSM write ε = `eps_nuc`, the chains' sum without the thermal neutrino loss, with that ε's derivatives `eps_eps_T`, `eps_eps_rho` (absolute, dε/dln T), as MESA writes `eps_nuc` with `d_epsnuc_dlnT` and `d_epsnuc_dlnd`; FGONG's `var(9)` is the same ε. `kap_kap_T` and `kap_kap_rho` are κ dln κ/dln T and κ dln κ/dln ρ.
- Errors return `ierr = 1`, which stops the run with exit status 1. io reports them through `io_units`: `check_io` after an open, read or write (`ERROR: cannot <action> <path>: <reason>`), and `report_error` otherwise (`ERROR: <text>`), on the terminal and in the run log once it is open. A starting model that cannot be read, whose zone count does not fit the arrays, or that ends early, is such an error, as is a profile column without a value in a region.
- The other messages go through `io_units` too, each on the terminal and in the run log: `report_warning` (`WARNING: <text>`, a probable mistake the run goes on with: the controls' warnings of `warn_inert_controls`, `warn_inconsistent_controls` and `derive_controls`), `report_note` (a line saying what the read did), and `log_line` (a line for the run log only: its header, the run plan). A message from before the run log opens waits for it: `open_run_log` writes the waiting lines first, so the run log holds them in order. A controls error stops the run before the run log exists: its message is on the terminal only.
- The `.mod` model holds one model, the latest (`write_mod_model(..., replace=.true.)`); the Monte Carlo model file holds one per run (`replace=.false.`). Its rows are written at full precision (es26.16e3), so a reload between cards gives the model back bit for bit.
- Paths: every path control may start with `{YREC_INPUT}`, `{YREC_START}` or `{YREC_OUTPUT}`: that environment variable's value, or `../../input`, `../../startmodels` or `output` when it is unset or empty.
- `pulse_format` is GYRE, FGONG or GSM, in any case.

**ctrl, job and the buffer.** `star%ctrl` holds the controls the run reads, and never changes after the read. `star%job` holds the controls that code outside the read assigns: the run-card arrays the calibration rewrites, the stop thresholds the stop conditions disarm, `atm_choice`, `fcorr`, `use_structure_dt_limits`, `use_mass_accretion`, the Monte-Carlo range; and the Monte-Carlo samples and the card cursor `nk`. An input-only control (one only the read uses: the S-factors, the readable tolerances, the per-vintage OPAL EOS paths) or an unused one stays in the read's buffer. The registry's `home` column says which (`ctrl`, `job`, `buffer`); `tools/check_boundaries.py` fails when the code disagrees (a ctrl member assigned outside the read, a job member nothing assigns, a buffer member code outside the read reads), and when the `used` column (`run`, `read`, `none`) does. A latch that the run switches and every card re-arms is a star member armed from its control (`star%settling_active` from `diffuse_helium_active`), not the control itself.

**A control's names.** A namelist matches a deck's entries by variable name, so the legacy decks fix the legacy spellings (`KTTAU`). Inside the code a control has its canonical name (`atm_choice`, in `controls_buffer`, `star%ctrl` or `star%job`); its inlist name is usually the canonical one. An inlist name that misdescribed its control was replaced, and the old one is still accepted as an alias (`new_zone_omega_weight` for `cz_rotation_law_exponent`, `kurucz_atm_table_file` for `kurucz_opacity_table_file`, ...; a deck setting both gets the new one's value). `defaults/controls_registry.tsv` maps the names and documents each control (`tools/controls_registry.py` describes its columns and the statuses `live`, `legacy`, `unused`, `derived`; `defaults/controls_registry.md` is the generated table). Derived code works on the canonical names; only the reader sees the legacy ones.

**Table paths.** Every table file is a string control in `star%ctrl` (`laol_table_path`, `zams_a_table_path`, `alex95_table_paths(7)`, ...; `opal_eos_table_path` is the OPAL EOS vintage's, derived). The builders in `setup/microphysics_settings.f90` copy them into each domain's paths record (`kap_table_paths_from_star`, `eos_table_paths_from_star`, `atm_table_paths_from_star`), which `kap_init`, `eos_init` and `atm_init` take (`install_run_settings`, `setup/settings_install.f90`).

**Where a check goes.** A value or combination the run cannot use: `check_controls`, with ierr = 1 and `report_error` naming the control (and its legacy name). A setting that is legal but inert: a warning in `warn_inconsistent_controls` (or, for a legacy-only name, `warn_inert_controls`), through `report_warning`. A domain's own consistency checks on its settings stay in the domain.

The wind law's coefficients, the convection zone's rotation-law clamp and the solid-body flag are not controls: `setup/rotation_settings_setup.f90` derives them when it builds rotation's settings (`magnetic_braking`'s `derive_wind_law`). The Bulirsch-Stoer controls (`tolerance_fraction`, `max_stage_index`, `extrap_order`) are controls in `star%ctrl`, and the envelope integration copies them into its kernel's settings (`envint_config`).

## 4. Tests and coverage

`test_io` (`make tests` in `src/`, then `pytest test_io.py`) checks io's own procedures against their contracts, with no deck and no tables (it writes every file it reads, in a scratch directory; `io/test/expected_test_io.out` pins the list of checks):
- `expand_value`: a leading placeholder becomes its environment variable's value (set through the C library), or its default when the variable is unset or empty; a placeholder that is not leading, a value without one and a value shorter than any placeholder stay as they are; a value that expands to a later placeholder is expanded again;
- `directory_of` (up to the last `/`, blank for a bare name) and `pulse_format_code` (any case, blanks around, anything else unknown);
- `parse_columns` on a small table: the default selection in its order; a file's names in file order, past comments and blank lines; an unknown name, a file that selects nothing, a missing file and more than `max_cols` names are errors with their messages, the unknown name's with the valid names in the run log;
- `nml_file_has_group`: a group found in any case, ended by a blank, a tab or `/`, and not as the prefix of a longer name or in a comment;
- the `.mod` model: written and read back bit for bit (every global, flag and column, at values from 1e-310 to 1e120), its columns line and a row in its order, an unknown global noted and skipped, replace and append, and the reader's errors (another columns line, a file cut inside its shells, too many zones); the format tag, and an empty file;
- synthetic YREC7 and MODEL2 files written in their layouts: every value where the layout puts it (the header, MODEL2's codes and flags, the luminosities and their conversion from erg/s, the envelope records and the reflected triangle, the structure, X and Z in units of 1e-6, the CNO and light-element blocks through the convection zones, He4 = 1 − X − Z − He3, omega and its sentinel, a rotating file without omega), and the files cut or damaged (a cut, a zone count of 0 or above `json`, a shell mass above the star's, a convection-zone edge outside the model);
- the history and profile column tables: names nonblank, short enough and unique, kinds valid, the default selections resolving in the `.list` order.

Each of these checks was confirmed to fail under a mutation of the code it covers.

`test_mesa_output.py`: the output contract on the solar deck: the exact file set; the history's layout, its rows against the progress lines, its integer id columns; `profile_number` against `profile_interval`; the profiles' layout (zone 1 the surface, through the atmosphere); a history columns file; FGONG files from `pulse_format = 'Fgong'`; GSM with `YREC_TEST_HDF5=1` on an HDF5 build. `test_default_columns_lists_in_sync` holds the column tables to the `.list` files: every table column in its list once, each row at the index named after it, the indices 1..n, a value for every history column, a case in each region for every profile column, and the generated include current (each of these was confirmed to fail under a mutation). `test_output_directory_is_created`: a nested output directory with a space in its path. `test_columns_file_path_is_expanded`: a placeholder in `history_columns_file`.

`test_mesa_baselines.py`: history.data, the profiles, the pulsation files and the `.mod` of two solar decks, byte for byte against `examples/run_standard_solar_model/standard/mesa/`.

`test_stop_conditions.py`: the structure-limit stops end the run with their message in the run log; the seismic history columns are opt-in. `test_reentry.py`: a second `run_yrec` in the same process equals a fresh process (the previous call's history file is closed by `output_open`). `test_error_exit.py`, io's cases: an unknown `pulse_format`; a MODEL2 starting model with too many zones, one cut inside its shells, and an empty one; each exits 1 with its message. `test_generated_files.py`: the generated files are current, and `expand_paths` covers every path control in the registry.

`test_controls` (`make tests` in `src/`, then `pytest test_controls.py`) reads every deck in `examples/` and `testsuite/` through `read_controls` and `open_run_files`, as a run does, and dumps every element of `star%ctrl`, `star%job` and of the buffer-only members (`buffer%<name>`), with the star fields the read sets; it compares the pristine dump, the representative decks' differences from it and a hash of every dump with `io/test/expected_controls/`. Any change to the read shows up here; regenerate with `YREC_REGEN_CONTROLS=1` after a deliberate change and check which lines moved. The same file checks, each against a mutation that breaks it: a deck setting nothing reads exactly `controls_state()`; without `use_new_rate_variables` the zoning and timestep factors are `zoning_tolerances` and `timestep_factors` at their defaults; card 1 starts from the starting model whatever `first_call_flag(1)` says; a second read into a used star starts from the defaults; the copy of the deck lands in the output directory; the Monte Carlo paths are expanded; the older inlist names (aliases) read as the new ones; a warning reaches the terminal and the run log. `test_inlist_convert.py`: a converted legacy deck runs identically. `test_boundaries.py` runs `tools/check_boundaries.py`, which checks the registry's `home` and `used` columns against the code. `test_error_exit.py`, the controls' cases: each controls error (semiconvection with overshoot, the envelope triangle, `max_diffusion_iters`, the Bulirsch-Stoer limits, `num_runs`) stops with exit 1 and a message naming the control. The controls generators themselves stop when the registry and the declarations disagree (a member without a row, a type mismatch, an alias on a legacy-named control).

**Coverage.** `python3 src/tools/coverage.py --work DIR --dir io --test test_io --test test_controls --deck ...` measures the line coverage of io/ under the test programs and the decks given (a -O0 --coverage build in DIR). With `test_io`, `test_controls` (the pristine defaults) and seven decks (cm_base, cm_rot_base and cm_atm_krishnaswamy; cm_base with profiles and FGONG files every 2 models; cm_base with GYRE files every 3 models, the interior GYRE file every 2 models and the isochrone file; five models from a YREC7 seed model; cm_base from a `.mod` starting model) it is 94.0% of 2275 lines (2026-10-29; 86.5% of 2065 before `test_io` and the `.mod` deck). The output and the model files: history_output, profile_output and output_columns 100%, run_log 97%, model_files 97%, run_files 94%, yrec_output and pulsation_output 91% (GSM is an HDF5 build's), run_cards 88%. The controls: controls_sync and legacy_controls 100%, controls_reader 85%, derived_controls 75%, controls_check 54% (its error branches, which `test_error_exit` runs).

## 5. Extending

**Add a history column** `<name>`:
1. If its value is new, add it to the star as `state/README.md` §7 says ("Add a star field": the member with its comment in the checked form, then `python3 tools/gen_star_docs.py`, which refuses a member without one), and compute it in `compute_observables` (`core/diagnostics/observables.f90`), after the step's physics.
2. In `io/history_output.f90`: its named index after the last, `ih_<name> = <n>` with `n_hist_cols = ih_<name>`; its row in `history_columns`, `cols(ih_<name>) = output_column('<name>', real_column)`; and its value in `history_values`, `vals(ih_<name>) = s%...`.
3. Its line in `src/defaults/history_columns.list`: `<name>` to write it by default, `!<name>` to make it opt-in.
4. Rebuild (make regenerates `io/default_columns.inc`) and run `pytest test_mesa_output.py -k lists_in_sync`, which checks the index, the row, the value and the list, and `pytest test_io.py` (a unique, short enough name, a valid kind).
5. A default column changes history.data: reseed `test_mesa_baselines.py` (remove `examples/run_standard_solar_model/standard/mesa/` and rerun it).

**Add a profile column** `<name>`:
1. If its value is new, add it to the star (`state/README.md` §7, as above) and compute it in the step, where its neighbours are computed.
2. In `core/diagnostics/stitched_model.f90`: its named index after the last, `ip_<name> = <n>` with `n_prof_cols = ip_<name>`; its row in `profile_columns`; its case in `interior_value`; and its case in `envelope_value` and in `atmosphere_value`, with the value there, or with the column added to the group that is zero above the fitting point. A column without a case in a region stops the run at its first model (`fill_stitched_arrays`), and fails the sync test.
3. Its line in `src/defaults/profile_columns.list` (or `!<name>`).
4. Rebuild, run the sync test and `test_io`, and reseed the baselines if the column is a default one.

(Both recipes were traced on 2026-10-29 by adding a column each way: the sync test passes, and the history and profile files carry the new column.)

**Add a field to the `.mod` model** (`io/model_files.f90`, and the star member it holds):
- A global value: its line in `write_mod_model` (a name padded to 20 characters, written with `mod_real_format`, `mod_integer_format` or `mod_logical_format`) and its `case` in `read_mod_model` (into the star, or into a new `model_file_header` field when the star does not hold it). An older file without it still reads (the member keeps its value); a reader that does not know a name notes it in the run log and reads on.
- A per-shell column: its name in `mod_columns`, and its value in `write_mod_model`'s row and in `read_mod_model`'s row read, at the same place. After the convective flag, `mod_row_format` takes it as it is (its last group repeats for as many values as the row holds); before it, the `6` of the six structure columns in `mod_row_format` becomes 7. The reader requires the columns line to be `mod_columns`, so older `.mod` files no longer read: change the tag (`YMOD 2`) and keep reading `YMOD 1` if they must. Update `test_io`'s round trip (its `fill_mod_model`, the columns line it expects and the row it reads back). (Traced on 2026-10-29 with `j_rot` after `be9`: the row format took it unchanged, and `test_io` failed on the columns line until its round trip was updated, then passed.)

**Read another starting-model format:** a reader `read_<format>(s, iread, header, ierr)` in `io/model_files.f90` beside `read_yrec7` (its records as named formats, every read with `iostat` through `check_model_read`, the zone count through `check_zone_count`), its tag in `core/model/starting_model.f90`'s `read_starting_model_file`, and a synthetic file of that layout in `test_io`, good and damaged.

**Add a control** (traced end to end on 2026-10-29 with a real dummy control read by rotation's settings, a logical one core reads and a dummy table path):
1. Declare it in `io/controls_buffer.f90`, in the group it belongs to, with its default as the initializer (`real(dp) :: my_scale = 1.0d0`). That is the only place its default is written.
2. Add its row to `defaults/controls_registry.tsv` (columns in `tools/controls_registry.py`): `group` (`control` or `physics`), `legacy` and `proposed_name` both the new name (the legacy namelists are frozen, so a new control is read only by the inlist format, and its inlist name is its code name), `type` as declared (`real`, `integer`, `logical`, `string`, with `(n)` for an array), `status` `live`, a description, `canonical` the new name, `home` `ctrl` (`job` if code outside the read will assign it, `buffer` if only the read uses it), `used` `run` (`read` for `buffer`), `aliases` empty.
3. From `src/`: `python3 tools/gen_controls_state.py`, `python3 tools/gen_inlist.py`, `python3 tools/gen_controls_dump.py`.
4. Give it to the domain that uses it: a field in the domain's settings type (`<domain>_configuration` or the domain's settings record), its copy in the builder in `setup/` (for rotation `rotation_settings_from_star`, for the network `net_settings_from_star`, for kap, eos, atm, convection and diffusion `setup/microphysics_settings.f90`), then `python3 tools/check_star_contracts.py --fix` for the builder's `star reads:` list (`tools/check_boundaries.py` fails until the builder sets the field). The domain reads the field, never `star%ctrl`.
5. If some values cannot run, reject them in `check_controls` (it reads the buffer's names); if a combination is inert, warn in `warn_inconsistent_controls` (it reads `s%ctrl`).
6. `make` in `src/`, `python3 tools/check_boundaries.py` (it checks the row's `home` and `used`), `python3 tools/gen_star_docs.py`, and `YREC_REGEN_CONTROLS=1 python3 -m pytest -q test_controls.py` from the repository root: only the new member's lines change (in `pristine.txt`, each representative dump that sets it, and every line of `hashes.txt`).

**Add a control the star layer reads directly** (a control of core's own drivers, `core/`, which take the star): steps 1-3 as above; then read it as `s%ctrl%my_flag` where it is needed (or `s%job%my_flag` with home `job` if core also assigns it, e.g. a latch: then prefer a star member armed from the control at each card, as `settling_active`); run `python3 tools/check_star_contracts.py --fix` (the procedure's `star reads:` line), `python3 tools/gen_star_docs.py`, step 6. A physics domain (`STAR_FREE_DIRS` in `check_boundaries.py`) never reads `s%ctrl`: give it a settings field instead.

**Add a table path** (a file a domain reads at init):
1. `io/controls_buffer.f90`: `character(len=256) :: my_table_path = ' '` beside the other table paths.
2. Its registry row as for a control (`type` `string`, `home` `ctrl`, `used` `run`), its inlist name `my_table_file` or the code name.
3. `io/run_files.f90`: `call expand_value(my_table_path)` in `expand_paths` (`test_generated_files.py` fails until it is there).
4. The domain's paths record (`kap_table_paths_t` in `kap/opacity_tables.f90`, `eos_table_paths_t` in `eos/eos_configuration.f90`, `atm_table_paths_t` in `atm/atm_tables.f90`): a field; its copy in the builder (`kap_table_paths_from_star`, `eos_table_paths_from_star`, `atm_table_paths_from_star`, `setup/microphysics_settings.f90`); the domain's init opens it (with newunit and iostat).
5. The generators, `check_star_contracts.py --fix`, step 6 of "Add a control".

The legacy CONTROL/PHYSICS namelists are frozen: a new control needs nothing in `legacy_controls`. A legacy name takes its canonical twin's default (`legacy_mirror.inc`); only the legacy names with no canonical home have defaults of their own, in `set_legacy_defaults`. `gen_inlist` stops if a control has no default in the code.

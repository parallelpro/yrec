## burn_lib / net_lib -- summary

`src/core/burn_lib.f90` (3105 lines) holds the burn drivers (eqburn, dburn/dburnm, deutrate, engeb + three internal subroutines, liburn/liburn2, lirate88); `src/net/net_lib.f90` (2424 lines) holds the pure kernels (neutrino, nulosses, azbar, sneut, rates, safedivexp, ifermi12, zfermim12). The physics is well-referenced (Bahcall Q-forms, CF88, Graboske screening, Itoh 1996) and the Batch 2/3 fixes are in place. The dominant maintainability problem is duplication, not physics: the 13-reaction rate/screening kernel exists twice (engeb 1230-1500 and net_lib `rates` 1894-2226), liburn/liburn2 share ~250 byte-identical lines, and dburn/dburnm are near-clones with different units. The 13 reactions are addressed by bare integer indices in six places (q-tables, `rate(1..13)`, `eg(50)`, `star%reaction_rate_1..13`, `cross_section_scale(14..17)`, `neutrino_flux(9/10)`), so adding a reaction means editing every one. Naming is mostly modern but a handful of comments and headers describe a code layout that no longer exists (common blocks, the reversed "merge into net_lib"). Almost everything below is class A; the one hard constraint is the measured bit-drift note at burn_lib.f90:1143-1149, which makes any extraction *inside* engeb's rate block class B in practice.

## Structural recommendations (3-5)

1. **One reaction table, one index scheme.** Where: new `src/net/net_def.f90` (or top of net_lib). Mechanism: `integer, parameter` names for the 13 reactions and the 4 extra scale slots; `type reaction_data` (Q1-Q8, zprd/z53/z43/z23/z86, eg, S0 scale slot) as a parameter array; `rate(13)`, `eg(13)`, `star%reaction_rate(13,json)` addressed by name. Enables adding a reaction by appending one table row and one energy line instead of touching ~6 index sites in two files. Cost: M-L (star_info field relayout, all `rate_*` callers in mix.f90 / timestep_limit_hburn.f90 / eqburn). Class A provided the data statements are copied verbatim and loop order is unchanged.
2. **Make `rates` the single rate kernel and have engeb consume it.** Today engeb re-derives the rates and screening (burn_lib 1230-1500) with its own derivative arithmetic. The honest version: keep engeb's inline block (the 1143-1149 bit-drift note forbids extraction) but move the *tables* (item 1) so both copies read the same data, and add a `test_net` check that engeb's `reaction_rate(i)` equals `rates`' output at the same (rho,T,X). Full de-duplication is class B and costs one reseed (~45 min) plus a derivative-consistent `rates` API; worth it only if a new reaction is actually planned.
3. **Collapse liburn/liburn2 around shared helpers.** Extract `locate_cz_base` (2165-2226/2695-2756) and `average_cz_abundances` (2337-2419/2810-2892) as module subroutines; keep the two drivers as thin shells that differ only in their timestep source and the safedivexp choice. ~250 lines removed. Class A (byte-identical arithmetic, no measured drift zone). Cost M, one pin run.
4. **Split compute_neutrino_emission and give engeb an explicit output record.** Replace the 20-argument engeb signature with a small `type burn_result` (eps by chain, deps_dlnT, deps_dlnrho, eps_nu, fluxes(10)) filled by three internal subroutines (item 4 above). Enables neutrino_flux_table and henyey_coefficients to stop passing 15 positional scalars. Class A if the arithmetic stays where it is; cost M (three call sites).
5. **Retire dburn/dburnm's unit split at the interface, not the body.** Give dburnm a header table of the four documented differences (units, threshold, weighting, rate source) and move the `timestep_gyr` conversion (470) and thresholds (336/503) into two named parameters each; do not unify (class B, and the ROADMAP note already justified keeping them). Cost S, class A.

## kap + atm tables -- summary

Scope: 51 files under `src/atm` and `src/kap` (all read in full; paths below are relative to `src/`). Numerics are already sound where the earlier sweeps looked; what remains is almost entirely *structural duplication* and *F77 residue*. The dominant pattern is "second-Z clones": `kurucz2`, `gtlaol2`, `opal92_interp2d_z2`, `opal92_interp3d_z2`, `kcsurfp`, plus mirrored second halves in `build_kurucz_splines`, `read_kurucz_tables`, `sulaol`, `rdlaol`, `opal92_table_prep`, `opal92_surface_table`, `read_opal92_tables`, `atm_init` -- roughly 1,100 lines that differ only by a `2`/`_z2`/`c` suffix. The second pattern is the hand-rolled 4-point-stencil search (13 copies across opal95/alex94/alex06) using the F77 loop-index-after-completion idiom. Third: three incompatible failure conventions coexist (`ierr`, alternate return `*100`, and silent EOF success in `ll95tbl`). Fourth: per-file `integer, parameter :: num_t/num_d/num_x` copies (7 for opal95, 7 for opal92, 4 each for alex94/kurucz) instead of one dimensions module -- the very class of drift that produced the ll95tbl 126/130 slot bug. Everything listed below is class A unless marked B; nothing here needs a reseed except the two `pow`/`exp10` and atomic-weight notes.

## Structural recommendations

1. **Table-set derived types instead of `_z2`/`2`/`c` clones.** Where: `opacity_table_lib.f90` (`kurucz_table_set`, `opal92_table_set`, `laol_table_set`), `atm_table_lib.f90` (`surface_p_table` for Kurucz/Castelli). Mechanism: each interpolator/reader/spliner takes `type(...), intent(inout) :: tbl`; `opacity_table%kurucz(2)`, `opacity_table%opal92(2)`, `opacity_table%laol(2)`; `kap_eval` picks `(1)` or `(2)` and blends. Enables: deleting `kurucz2.f90`, `gtlaol2.f90`, `opal92_interp2d_z2.f90`, `opal92_interp3d_z2.f90`, `kcsurfp.f90` and the mirrored halves in 8 setup routines (~1,100 lines); a third Z table or a new low-T family becomes an instantiation, not a copy. Cost: L (touches opacity_table_lib, setupopac, kap_lib dispatch, atm_init). Class A.
2. **One family interface + result type.** Where: `kap_lib.f90` and each family driver (`kurucz`, `gtlaol`, `opal92_interp3d`, `getopal95`, `getalex06`, `alex94_interp3d`). Mechanism: `type kap_result` (kappa, log10 kappa, dlnk/dlnrho, dlnk/dlnT), every driver `family_eval(logrho, logT, X, Z, res, in_table, ierr)`; `kap_eval` becomes a `select case` dispatch plus the ramp/blend helpers. Retires the alternate return, the getopal95 hidden-argument chain (`opal95_interp2d/3d/4d` take *no inputs* -- everything arrives via `opacity_table%opal95_logr/weight_*/index_*` set at `getopal95:54-219`), and the mixed failure conventions (ierr / `return 1` / silent EOF). Cost: L. Class A for existing paths.
3. **Shared stencil kernels in `numerics_lib`.** `stencil4_locate(grid, n, x, cursor, mode)` for the 13 searches (finding 6) and `lagrange4_sum(w, a, b, c, d)` for the 4x4 / 4x4x4 weighted sums in `opal95_interp{2,3,4}d`, `getalex06:124-152`, `alex94_interp3d:123-204`, `alex06tab:92-141`, `opal95_fixed_z_table:61-125`. Byte-safety requires preserving the left-to-right association `w1*a + w2*b + w3*c + w4*d` in the helper; then A, else B. Cost: M. Enables: any new Lagrange-tabulated opacity family is ~100 lines instead of ~400.
4. **`kap_table_dims` module.** One `integer, parameter` block per family (`opal95_nt=70, nd=19, nx=10, nz=13, n_slots=130`, `opal92_*`, `alex94_*`, `alex06_*`, `kurucz_*`, `laol_nx=12, nrho=104, nt=52`) plus the empty-cell sentinels; `opacity_table_lib.f90` and `atm_table_lib.f90` (currently raw `57/11/76`, `12/104/52` literals next to `atm_table_nt` parameters) declare arrays from it and the ~30 per-file copies are deleted. Cost: S-M. Class A. Directly prevents the dimension-drift class (ll95tbl 126/130).
5. **Finish the state move and remove foreign writes.** Move the bare module variables in `opacity_table_lib.f90` (LAOL set, `use_pure_z_table`, `tollaol`) and the Kurucz atm arrays in `atm_table_lib.f90` into the types with modern names; delete the dead members (finding 17). Make loaders return what they learn instead of writing elsewhere: `rdlaol.f90:63` -> return `debye_huckel_z` to `setupopac` which hands it to the EOS; `setupopac.f90:35` -> `kap_init` returns `two_z_active` rather than setting `star%use_two_z_tables`. Cost: M. Class A. Enables the check_boundaries `STAR_BLIND_FILES` claim in `kap_lib.f90:30-33` to become true.
